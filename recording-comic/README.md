# README 首屏演示录制页

这个文件夹保存的是一个独立、临时的三格漫画页面，用于制作 Orbit Video Viewer 开源项目在 GitHub 和 Hugging Face 上的首屏演示视频或 GIF。

## 为什么制作这个页面

Orbit Video Viewer 的核心能力是：把一段已经生成好的环绕视频转换成可由鼠标拖动视角的网页交互。

普通产品界面能够证明功能可以运行，但不容易在 README 的第一眼同时展示“漫画应用场景”和“拖动后视角发生变化”。因此增加了这个专门用于录屏的页面：静止时看起来是一张完整的黑白漫画页，鼠标进入第一格并拖动时，主画面的观察角度会连续变化。

这个页面不是新的产品功能，也不是漫画编辑器。它只是开源发布阶段的展示素材制作工具，与正式 Demo 和 Core SDK 分开保存。

## 页面具体做了什么

- 使用“上方一个大横格、下方两个并排格”的三格漫画布局。
- 第一格接入现有 `OrbitViewer` SDK，可以用鼠标水平拖动改变视角。
- 第一格直接复用项目已有的 `video_01.mp4` 环绕视频，没有重新生成视频。
- 第一格加载前使用 `img_01.png` 作为静态画面。
- 下方两格使用 `img_02.png` 和 `img_03.png`，保持静止并尽量完整显示。
- 加入少量英文漫画文字，避免页面变成技术说明页。
- 页面外围使用纯白背景，即使录屏或截图时上下带有留白，也会呈现漫画纸张的感觉。
- 没有修改或重新实现 Core SDK，也没有覆盖原 Orbit Comic Demo。

## 两种使用模式

### 1. 正常交互模式

打开：

```text
http://127.0.0.1:5173/recording-comic/
```

用户可以亲自把鼠标移入第一格并左右拖动。这个模式适合手动录制新的演示素材。

### 2. 自动录制模式

打开：

```text
http://127.0.0.1:5173/recording-comic/?capture=1
```

这个模式会自动模拟一段短演示：

1. 箭头光标从页面留白处进入第一格；
2. 光标变成抓手；
3. 抓手左右拖动；
4. 第一格随之切换环绕视角；
5. 下方两个分镜始终保持静止。

自动模式只用于录制，不会出现在普通交互页面中。

## 本地启动

在 `orbit-panel-viewer` 项目根目录运行：

```bash
pnpm install
pnpm dev
```

然后打开上面的正常模式或自动录制模式地址。不要直接双击 HTML 文件，因为 MP4 解码和模块加载需要通过本地开发服务器运行。

## 已生成的展示文件

`output/` 目录中包含当前生成的成品：

- `orbit-comic-demo.mp4`：约 8.3 秒，1200×832，适合视频上传或进一步压缩；
- `orbit-comic-demo.gif`：约 8.3 秒，800×555，可直接作为 README 动图预览。

如果重新录制，可以替换这些输出文件，但不需要改动 SDK 或原始环绕视频。

## 文件关系

```text
recording-comic/
├── assets/            # 录制页下方两格的静态分镜
├── index.html          # 三格漫画结构
├── main.ts             # SDK 接入和自动演示流程
├── style.css           # 漫画分镜、白底和光标样式
├── output/             # 已生成的 MP4 和 GIF
└── README.md           # 本说明
```

页面通过现有工程读取以下素材：

```text
../public/demo/video_01.mp4
../public/demo/poster.png
./assets/shot.png
./assets/impact.png
```

录制页所需文件现在都位于公开仓库内部，可以在独立 clone 后复现，不再依赖仓库外的相邻目录。`assets/shot.png` 和 `assets/impact.png` 只服务录制页与生成的首屏素材，不属于 SDK，也不会进入正式 Demo 的生产构建。

## 开源发布时的定位

建议将生成的视频或 GIF 放在项目主 README 的首屏，用来快速说明交互效果；这个录制页面本身可以保留为可复现展示素材的辅助页面，但不应被描述成 SDK 的必要组成部分。

核心开源内容仍然是 `OrbitViewer` SDK。这个文件夹只负责把核心能力放进一个容易理解、容易录制的漫画场景中。
